你和我可以同时编辑同一个文档：我改了另一段，那段会原地更新、你的光标和滚动位置不动，改动处还会浮现约两秒的淡色强调；你改第 3 段、我改第 50 段，两边自动合并都保留；只有当你我改到**同一段**时，那段会原地展开一张"上下对照卡"（上是你的、下是我的），给你「用我的 / 用 Oru 的 / 两个都留」三个选择。任何被覆盖的版本都会进修改历史、标注"被 Oru 改动覆盖前的版本"，一键能恢复。

**开卡这一刻，你我的两个版本就各存一份进修改历史了**——不用等你选完，哪怕卡挂着几小时、中途崩溃，两版都在历史里找得回（你选完后，落选的那份还会补一个"冲突落选"标，手动拼合则两版都标"冲突版本"）。冲突卡开着、还没定夺时，我对**这一个文件**的后续修改会先搁着不落（对别的文件照常写）——等你拍板，我再拿着结果和文件最新内容重新决定接着改还是重写，不用你再开口催。

我合并进来的内容算"外部变更"，**不进你的撤销栈**——按 Ctrl+Z 撤掉的仍是你自己敲的字，而不是我刚合并进来的段落；想撤掉我的改动，去修改历史里翻。

**限制**：只有 Markdown 文档享受"不同位置自动合并"和同段对照卡；**表格撞笔时以我写的为准**——你正改某个单元格、还没自动落盘的那几百毫秒里我若写了这张表，你这笔在途输入会被我的版本覆盖掉（不弹对照卡，但被覆盖的整表版本仍进修改历史能找回）。演示稿、网页也只做"看到改动 + 被覆盖能找回"，不自动合并。不做多人实时镜像——不显示我的光标、不逐字符同步。

**怎么用**：你正编辑时直接让我改这份文档即可，Markdown 里的同段冲突会原地弹卡让你定夺；卡开着时我这个文件的后续改动会等你选完再接着来。表格则以我写的为准，重要的在途改动先停一下等它落盘。
