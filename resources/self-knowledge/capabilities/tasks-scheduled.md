顶栏「定时」进入定时任务清单：设一段到点自动替你跑的指令。**一个任务可以挂多条触发时间**——比如「每天早上 8 点 + 每周一下午 2 点」都跑同一件事，在清单里合成一行、到点各自触发。新建只需填执行内容、触发时间、在哪运行（每次新建对话 / 在指定对话里 / **推送到渠道**）。我直接执行不再反问频率。

**桌面新建的触发时间分「计时器 / 闹钟」两种**：计时器＝从现在起每隔 N 分钟 / 小时、共跑 M 次（**必须设次数、没有「一直」**，避免无限循环；只跑 1 次就是「N 分钟后一次」）；闹钟＝每天或每周某个钟点（星期多选，时间用滚轮选），可以「一直」跑或「N 次后停」。点「添加触发时间」加第二条、第三条。我在对话里帮你设时用的是同一套底层节奏（一次 / 每天 / 每周 / 间隔重复），一条指令里也能一次给你配好多条。

**产出可推送到渠道（发给某个认证的人）**：运行位置除了「新建对话 / 指定对话」，还能「推送到渠道」——本质是**选一个已认证的人**，到点把结果推到他的飞书 / Discord 聊天，你在手机上也收得到。桌面新建表单里选「推送到渠道」时：**没有可推送的认证用户就提示先去私聊绑定；只有一个人时自动选中不用挑；有多个就下拉选发给谁**。产出照常也落进一条承载对话（复用该人当前的活跃对话，已归档或还没有就新建一段并绑定）。**你在飞书 / Discord 里直接让我定时做点什么（如"每天早上给我讲个笑话"），我默认就把结果推回你正聊天的这个渠道**，不用你特意指定；只有在桌面对话里建的任务才默认走桌面新对话。推送失败（如网络问题、对方聊天失效）会在承载对话里留一条可见提示，不会闷声丢掉。

**历次运行可回溯**：每次执行都记一笔运行记录（时间 + 结果 ✓/✗/⏹ + 产出落在哪条对话）。任务行的「⋯」菜单里有「运行记录」，翻出历次执行一览，成功那次点「查看产出」直接跳到承载对话看当时的产出——不必再去各个触发对话里翻。

**到点即在后台跑，不等对话空闲**：到点那一刻就有一个后台执行体替你开跑——带一份当时的对话历史快照做上下文，机制和我派出去干活的后台任务同一套。它不占用对话回合，跑得准时、不受对话忙不忙影响，也不会被别的任务的长回合拖迟。开跑当下承载对话里就出现「执行中」状态（临时的，不写进历史，应用重启就消失）；跑完后翻出一张「定时任务结果」卡标成功 / 失败，执行体写出的**产出原文会直接作为我的消息落进那个对话**（不经转述、不排队）。我在下一回合会经系统旁白知悉「这个定时任务已经跑完、产出已经发给你了」，不会不认账、也不会重复再跑一遍。同一个任务的执行是**串行**的：上一拍还没跑完，新到点的那拍不另起、跟进行中的合并算一次，短周期任务撞上长执行不会堆出一堆并发副作用。

**设时间靠谱**：你跟我说"今晚六点提醒我"，我只需说清"什么时候"（日期 + 钟点 / 星期 / "多久之后"），换算成机器时间由代码统一做——和你手动设置页同一套，我不再自己心算时间戳（那是最容易算错的一步）。一次性提醒若时刻已经过去，会在创建时被当场拦下、我重设而不是假装"设好了"；确认卡上也会显示解析后的具体时刻，方便你核对日期有没有错。

**限制**：不碰 cron 表达式（没有自定义频率项），最小触发间隔 1 分钟。**不做云端常驻**——应用没开就不触发。到点有个约 5 分钟的**宽限窗**：落后在宽限内的照常当到点跑；超过宽限（关机 / 长时间休眠错过的）不自动补跑（机器判断不了这内容还值不值得补），进"错过待处理"区由你决定执行或忽略（一个任务有多条触发时间时，「执行」补跑这个任务所有错过的那几条、「忽略」忽略整个任务的错过）。你手动点「执行」补跑那一次**不计入**「跑满 N 次」的配额。触发失败不自动重试、如实记下交给你。任务带时区锚，你换了时区后每天 / 每周类的下次时刻会按新时区重算。本期没有系统级桌面通知，靠对话内的结果卡 + 未读提醒。

**已结束怎么看**：已结束的任务行没有开关（它没有下次触发）。"已结束"筛选下分两组——「已触发」（真的触发过的，每行标记区分「✓ 成功 / ✗ 失败 / ⏹ 已中止」）和「未能触发」（从没跑成就结束的，每行带一句浅色说明，如"设定时间已过，未执行"或"你已忽略"）。其中「已中止」= 到点跑起来后你主动按了停止：它既不算成功、也不算失败（不会误报进"需你处理"的通知），只是如实记下"这一轮被你叫停了"。

**前提**：我创建 / 修改 / 删除 / 暂停 / 启用定时任务都会走审批确认卡；只是查询不用确认。

**怎么用**：在定时任务页新建，或在对话里让我帮你设。我在对话里帮你建成后，消息下方会出现一张确认小卡（任务名 + 频率 + 下次运行时刻），点「管理」直达定时任务页；后来任务被改动，卡上显示的始终是当前最新设置。
